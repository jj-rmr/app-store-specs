IdeaPatch application architecture and agent notes

- Purpose: CodeCanvas is the SPECS student developer community and project catalog. It helps students discover software, share projects, find collaborators, and exchange constructive feedback. Keep implementation minimal and demo-ready.
- Brand: Reuse `src/components/Brand.tsx` for every product lockup. The stitched yellow patch and lightbulb mark plus the CodeCanvas wordmark are canonical.
- Formatting: Run `npm run format` after maintained-file changes and `npm run format:check` when validating. Respect `.prettierrc.json` and `.prettierignore`; do not manually introduce competing formatting conventions.
- Vite types: Preserve `src/vite-env.d.ts` and its `vite/client` reference. It is the canonical declaration source for CSS side-effect imports, static assets, and `import.meta.env`; do not replace it with an untyped catch-all declaration.
- Layers:
  - UI: React components under `src/pages` and small presentational components.
  - Auth: `src/auth` contains `AuthProvider` and `mockCredentials.ts`. Swap in real auth later.
  - Data: In-memory list for submissions; replace with API + DB later.
- Design system: Reuse `toon-card`, `toon-button`, `toon-input`, `toon-label`, `paper-note`, `project-cover`, `sketch-underline`, and `ink-stamp` from `src/styles/tailwind.css`. Reserve the strongest hard navy shadows for interactive controls and preserve the 6px button press travel. Informational cards should resemble lighter workshop paper artifacts rather than generic neo-brutalist blocks.
- Colors: Keep all palette and opacity color values in the `@theme` block in `src/styles/tailwind.css`; use the generated Tailwind utilities or CSS variables in components instead of hardcoded colors.
- Background: Preserve the graph-paper grid, faint dotted grain, and pink notebook margin on the root canvas plus the oversized fixed `body::before` layer in `src/styles/tailwind.css`. The root copy supplies the elastic-overscroll canvas, while the pseudo-element extends beyond every viewport edge to keep vertical and horizontal pinch-zoom panning covered without relying on iOS-incompatible `background-attachment: fixed`; preserve its notebook-margin alignment. Do not clip the canvas at `html` or `body`; clip accidental content overflow at `#root` and app-container boundaries. Keep `html`, `body`, and `#root` shrinkable below 320 CSS pixels for browser zoom, and do not disable vertical overscroll or scroll chaining globally.
- Scrollbars: Preserve the global `--ink` track and corner with the `--yellow` thumb and WebKit buttons in `src/styles/tailwind.css`, including the Firefox fallback, so page and horizontal overflow areas use the defined sketchbook palette.
- Typography: Fontsource packages provide locally bundled Fredoka 700 for the CodeCanvas wordmark and Nunito 400/700/900 for all page headings, controls, and body text. Keep imports limited to these weights and Latin subsets; do not add remote font requests. Preserve the matching pre-mount font requests and timeout in `src/main.tsx` plus the initial loader in `index.html` to avoid first-load font swapping and layout shifts.
- Font persistence: Preserve the narrowly scoped service worker at `public/font-cache-worker.js`. It must remain cache-first for font requests only; avoid broad offline caching unless the architecture is intentionally expanded and documented.
- Icons: Use Phosphor React icons throughout the product, with `duotone` as the default playful style and `bold`/`fill` where clarity needs more weight. Avoid mixing in emoji, Unicode arrows, or ad hoc text-symbol icons.
- Screens and routing: `Home.tsx` owns `/`, `Login.tsx` owns `/signin`, and `Store.tsx` provides three focused destinations: `/store` for the searchable and filterable project catalog, `/builders` for developer profiles, and `/community` for activity; `/apps` and `/dashboard` are compatibility entries for Discovery. Navigation uses History API to preserve the in-memory demo session. On small screens, keep the brand/sign-out header fixed at the top and three menu actions fixed in a compact, non-scrolling bottom bar; match content padding to both fixed bars. At the large breakpoint, restore the fixed 280px sidebar. Keep the toon-like paper details restrained and preserve clear hierarchy between page title, filters, and results.
- Viewport: Preserve the `maximum-scale=1.0` and `user-scalable=no` viewport settings in `index.html`; touch pinch zoom is intentionally disabled to keep the fixed app shell stable.
- Actions: Every visible button or action link must have unique, implemented behavior. Remove duplicate-destination and placeholder actions; present non-interactive project/resource information as content rather than controls. Responsive copies are acceptable only when CSS ensures users see one at a time.
- App submissions: Require an app name, concise description, and valid URL. Store the URL with the in-memory app record and expose it through an external `Open app` link using `target="_blank"` and `rel="noreferrer"`.
- Agent notes: Treat `design.md` and `agent.md` as required companion files for every implementation change. Review both on every change and update both whenever architecture, behavior, dependencies, conventions, or design decisions are affected.
