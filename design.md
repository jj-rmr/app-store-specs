Design decisions

- Brand: The product is named **CodeCanvas**, a SPECS student developer community and app catalog. Use the reusable `src/components/Brand.tsx` lockup: the yellow stitched patch and lightbulb paired with the CodeCanvas wordmark.

- Tech: Vite + React + TypeScript for small, fast dev DX.
- Formatting: Prettier is the canonical formatter with project rules in `.prettierrc.json`. Use `npm run format` to write changes and `npm run format:check` for non-mutating validation; generated output, dependencies, lockfiles, coverage, and environment files are excluded through `.prettierignore`.
- Type declarations: Keep `src/vite-env.d.ts` with the standard `vite/client` reference so TypeScript recognizes CSS, static asset, and Vite environment imports without broad custom module declarations or relaxed compiler checks.
- Styling: Keep a restrained toon-like sketchbook treatment for an undergraduate computer science community. Define all palette and opacity colors in the `@theme` block in `src/styles/tailwind.css`; use the softened ink, paper, violet, mustard, teal, and muted accent colors through theme utilities or CSS variables. Preserve hand-drawn paper details and outlines, but avoid candy-bright color combinations, oversized playful lettering, and excessive card framing.
- Background texture: The page canvas combines a 24px graph-paper grid, faint 22%-opacity navy dots, and a pink notebook margin over cream. It should read as working paper rather than a decorative dot pattern. Paint the texture on the root document canvas so natural elastic overscroll reveals the design, and repeat it on a fixed, non-interactive `body::before` layer extended beyond every viewport edge so vertical or horizontal pinch-zoom panning cannot expose a blank background. Keep the notebook margin aligned to the original viewport inside that oversized layer. Do not clip this canvas layer at `html` or `body`, and do not rely on `background-attachment: fixed`, which is unreliable on iOS WebKit. Clip accidental content overflow at `#root` and app-container boundaries instead, and allow the document roots to shrink below 320 CSS pixels when browser zoom reduces the effective viewport.
- Scrollbars: Use the defined navy `--ink` color for the track and corner, with the defined `--yellow` color for the rounded thumb and scrollbar buttons. Apply the treatment globally, including horizontal filter rails, with Firefox and WebKit-compatible rules.
- Typography: Self-host fonts through Fontsource rather than a runtime CDN. Use Fredoka only for the CodeCanvas wordmark; use Nunito at weights 400, 700, and 900 for headings, controls, and body copy. Load only these selected weights and their Latin subsets in `src/main.tsx`. Before mounting React, explicitly request every used weight to prevent fallback-font layout shifts; race loading against a 1.5-second safety timeout and show the lightweight branded dot loader meanwhile.
- Font caching: Register `public/font-cache-worker.js` after the page loads. It uses browser Cache Storage with a cache-first strategy only for requests whose destination is `font`, complementing Vite's content-hashed HTTP caching without affecting pages, scripts, styles, or API traffic. Change the cache version only if the caching policy itself changes.
- Icons: Use `@phosphor-icons/react` for interface and decorative icons. Prefer rounded `duotone` icons for playful visual moments and `bold` or `fill` for small actions and status marks. Keep icon sizes consistent within a control, pair unfamiliar icons with text, and use `aria-hidden` for decorative icons. Do not mix emoji or text glyphs into the interface icon language.
- Interaction: Primary interactive controls use the shared `toon-button` class. The border and hard shadow must use the same `--ink` color; the resting shadow is 6px down, and `:active` translates the control down 6px while removing the shadow so it appears physically pressed into its shadow. Preserve visible focus states and reduced-motion support.
- Action economy: Render a button or action link only when it performs a real, distinct operation. Avoid repeated calls to the same destination on one page and never show action affordances on static placeholder content. Responsive variants of the same essential action, such as sign-out, are allowed when they are never visible simultaneously.
- Layout and routes: `/` introduces CodeCanvas and `/signin` contains authentication. The signed-in navigation has three destinations: `/store` is the searchable, filterable project catalog, `/builders` contains developer profiles, and `/community` contains activity and community standards. `/apps` and `/dashboard` remain compatibility entries for Discovery. Sidebar navigation updates browser history without reloading the demo session. On small screens, use a compact fixed top brand header and a compact fixed, non-scrolling three-column bottom navigation bar; reserve matching top and bottom content space so neither bar overlaps the page. At the large breakpoint, restore the fixed 280px left sidebar and horizontal icon-and-label buttons. Keep clear visual separation between the page heading, catalog filters, and project results.
- Auth: Mocked credentials located in `src/auth/mockCredentials.ts`. Auth layer uses `AuthProvider` so real auth (OAuth, backend) can be swapped in later.
- State: Local UI state powers the searchable and filterable community catalog, app submissions with validated external project URLs, and reversible upvotes. Submitted app links open in a new tab with safe external-link attributes. Persistent profiles, comments, moderation, storage, and backend APIs will be added later.
- Performance: Keep dependencies minimal; use React 18, strict typing, and avoid heavy libraries.
- Accessibility: Prefer semantic HTML and accessible inputs; keep contrast and focus outlines by default. Pinch zoom is intentionally disabled through the viewport metadata to keep the fixed app shell stable on touch devices.
- Documentation: Every implementation change must include a review and, when relevant, an update of both `design.md` and `agent.md` so the documented design stays aligned with the application.
